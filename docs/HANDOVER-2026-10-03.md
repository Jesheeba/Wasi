### 7.2 Single-send retry, Authentication excluded (`server/src/services/messagingService.js`)
Retries one network-level failure only. Never when Meta answered (`err.metaError`), never on a timeout
(Meta may already hold the message). **Authentication templates never retry** (a duplicate one-time code can
invalidate the first; the caller gets the 502 and can request a fresh code). A template whose category is
unknown locally also never retries (fail closed, like the consent gate). Known gap: an OTP sent through a
Utility or Marketing template is still retried; if you want that closed too, add
`|| looksLikeAuthenticationContent(template.body)` (already in `templateParams.js`). The connection is
already released before the Meta call, so the 750 ms wait pins no pool slot. Validated in scratch with the
real `metaClient` and a stubbed `fetch`: text, Utility, Marketing retry once and succeed; Authentication and
unknown-template make one call and fail; Meta 131042/131056 and timeouts make one call.
```diff
+// Retry ONE network-level failure ("fetch failed"). Never when Meta answered (err.metaError) and never on a
+// timeout: in both cases Meta may already hold the message and a second send would duplicate it.
+async function withTransientRetry(fn, { retry = true } = {}) {
+  try { return await fn(); }
```
